The re-enqueue of the current task (`PriorityScheduler::preempt_reenqueue_only` for yield and the deferred timer preempt, `on_preempt_selection` in-lock) is an ordinary user push under the same `MAX_RUN_QUEUE` (64) limit, and a refusal keeps `current` (`ContinuedCurrent`; split routes `YIELD_SPLIT_REFUSED reason=reenqueue_failed`, `TIMER_SPLIT_PREEMPT_DEFERRED … settlement=continue_current`).
